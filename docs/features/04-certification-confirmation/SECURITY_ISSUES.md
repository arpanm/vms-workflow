# F04 Certification and Confirmation — Security Issues

**Disposition:** every finding below is **Open**. `P1` means a local security/release blocker; `P2` is important hardening that must be resolved before production exposure. “External” identifies a controlled-environment acceptance dependency and is not used to defer a local control.

| **F04-SEC-005** | **Deadline and captured token policy are not enforced.** `act` accepts `AWAITING_RESPONSE` without comparing request `due_at` to the clock ([BusinessConfirmationService.java:257-267](../../../backend/src/main/java/com/vms/workflow/application/BusinessConfirmationService.java#L257-L267)). | **F04-SEC-006** | **No local outbox/worker, retry, reminder, expiry, or secure-link handoff exists; quorum notification is unsafe.** The adapter always returns `NOT_CONFIGURED` ([ProviderNeutralCertificationEmailAdapter.java:21-25](../../../backend/src/main/java/com/vms/workflow/application/ProviderNeutralCertificationEmailAdapter.java#L21-L25)) and no production code invokes `send`. ## P2 — Important hardening and proof gaps

| ID | Finding, exact evidence, and exploit | Impact | Required remediation | Reconciles |
|---|---|---|---|---|
| **F04-SEC-011** | **Public error detail can disclose restricted data and F04 lacks a stable correlation contract.** The handler emits exception messages in 404/400/409 responses ([ApiExceptionHandler.java:21-62](../../../backend/src/main/java/com/vms/workflow/api/ApiExceptionHandler.java#L21-L62)); the browser displays `ApiError.message` ([query-boundary.tsx:103-119](../../../src/features/certification/query-boundary.tsx#L103-L119)). F04 service-generated correlation IDs are not boundary-generated/returned consistently. A future provider/DB/validation error can render restricted MIME, recipient, token-adjacent or implementation detail. | Privacy leakage and poor incident correlation; weakens non-disclosure controls. | Return allowlisted problem code/messages and a request-bound correlation ID in every success/error header/body; log detailed diagnostics server-side with redaction. Frontend should render curated code text plus correlation ID only. Contract-test error bodies, OpenAPI header, console, and network redaction. | `F04-BE-015`, `F04-FE-012`, `F04-FE-TEST-004`; `T-F04-SEC-003`. |
| **F04-SEC-012** | **Rate limiting, CSRF future-safety, HTTP hardening, and deployment/dependency controls are absent.** CSRF is globally disabled ([SecurityConfig.java:25-32](../../../backend/src/main/java/com/vms/workflow/security/SecurityConfig.java#L25-L32)); this is acceptable only for today's bearer-header API, while the browser sends `credentials: "include"` ([api-client.ts:86-93](../../../src/lib/api-client.ts#L86-L93)) and a future BFF is planned. Local DB defaults remain in development config ([application-local.yml:2-10](../../../backend/src/main/resources/application-local.yml#L2-L10)); Compose uses a floating `postgres:18-alpine` image ([compose.yaml:1-9](../../../backend/compose.yaml#L1-L9)). | Token/action CPU or request-volume abuse, unsafe cookie-auth migration, and weak supply-chain/deployment assurance. No active cookie-CSRF exploit was demonstrated against the current bearer-only backend. | Decide and enforce bearer-only same-origin/strict-CORS or BFF-cookie architecture before deployment; enable CSRF/origin controls for ambient cookies. Add per-identity/IP limits for confirmation, webhook, outbox replay, export and login; add CSP/HSTS/referrer/permissions policy at the deployment edge; fail production without secret-manager values; pin images and add SBOM/SCA/SAST/secret/container scans in CI. | Inherited F01 architecture/dependency concerns; `F04-TASK-022/025/026`, `T-F04-SEC-003`. |
| **F04-SEC-013** | **Security proof is incomplete and current F04 tests fail.** The focused Testcontainers lane produced 15 failures and one error, including cross-scope, scope mutation, SOD, expiry, wrong-project action, quorum, and evidence controls. Tests are transactional/serial where real commit/race behavior is required ([TEST_ISSUES-BACKEND.md](TEST_ISSUES-BACKEND.md)); browser tests are intercepted and do not reach Java/Security/PostgreSQL ([TEST_REVIEW-FRONTEND.md](TEST_REVIEW-FRONTEND.md)). An attacker can exploit a regression that the current suite does not observe. | No release evidence for PRD 14 and `T-F04-SEC-*`; passing frontend fixture cases cannot certify server security. | Gate release on passing direct HTTP + independent-transaction Testcontainers matrices: unauthenticated/disabled/wrong org/engagement/project/deliverable/SOD/service identity; token theft/expiry/replay/rate; provider/inbound/attachment quarantine; direct restricted-role SQL; audit/security events; and concurrent action/outbox/replay. Keep controlled provider tests explicitly external. | `F04-TEST-002–005`, `F04-FE-TEST-002/004/005`; supersedes the stale premise of `F04-BE-012`; `T-F04-SEC-001–004`. |

## Duplicate and disposition reconciliation

- `F04-BE-001`, `-003` through `-011`, `-015`, and `-016` remain open and are mapped above; they are not re-filed as duplicate product issues.
- `F04-BE-002` is also open: invalidation resolution is structurally blocked and closure/reopen facts lack full guards. It contributes to F04-SEC-001/010 and must be corrected with append-only effective-resolution lineage, not by weakening immutability.
- `F04-BE-013` (policy versioning) and `-014` (recipient dedup/template governance) remain open design/operational integrity issues. They do not create a separate security ID here; captured policy use and recipient disclosure are already covered by F04-SEC-005/009.
- `F04-BE-012` is stale only in the narrow claim that no F04 test classes exist. Its gate conclusion is still open because the available F04 lane fails and does not cover the required adversarial cases (F04-SEC-013).
- No live email, mailbox, SSO/OTP/MFA, or F05 provider acceptance was attempted. Those are external controlled-environment gates after the local P1 findings are fixed.
