# F04 — Certification, Communication and Confirmation Tasks

**Phase:** 4
**Traceability:** RQ-018–RQ-023, RQ-030–RQ-031; PRD 08–09, 13–16, 20–22.
**Controlling stack:** Java 25 / Spring Boot 4.1.0 / PostgreSQL + Flyway / Vite React + TanStack. Do not add or restore Lovable or Supabase dependencies, migrations, clients, or browser-side provider credentials.

## Scope and delivery boundary

F04 turns the F03 effective frozen plan/baseline and its immutable Linear snapshots into a controlled monthly workflow: vendor submission, item-level product-owner certification, clarification and carry-forward, certification summary, auditable confirmation request/action, readiness, and close/reopen orchestration. It also consumes the F02 attendance snapshot as evidence. It does **not** calculate attendance, edit a frozen plan, infer delivery acceptance from Linear, generate the F05 procurement package/invoice, or silently create a business approval.

The locally implementable vertical is provider-neutral and testable with Testcontainers PostgreSQL plus fake/recorded email, object-storage/scan, identity and inbound-mail adapters. Implement server-side APIs, persistence, authorization, outbox/job contracts, and React workflows now. The following are **external acceptance**, not work that may be simulated as production-ready: selection/approval of email provider and dedicated monitored mailbox; sender domain/provider credentials and callback signing material; inbound-reply subscription/polling authority and raw-MIME retention; production recipient groups, quorum, delegates, SLA/escalation and exception policy; SSO/OTP/MFA policy; and live sandbox/production delivery. Until supplied, expose `NOT_CONFIGURED` / `ACTION_REQUIRED`, retain fixture evidence, and do not send real mail.

### Existing-contract dependencies

- F01 identity/RBAC supplies JWT principal, active membership, scoped engagement permissions, delegations, audit convention, and safe `404`-style denial. Add permissions rather than trusting a role sent by the client.
- F02 supplies immutable `attendance_snapshot_versions` (and any authorized exception/reopen semantics). Certification may proceed without it; confirmation readiness may not.
- F03 supplies one frozen effective `delivery_plan_version`, `delivery_plan_baseline`, immutable deliverable versions/criteria, recipient snapshot, plan-time Linear snapshot and current/snapshot projections. F04 must reference their IDs/checksums and never mutate them.
- F05 owns evidence-package, invoice-readiness and Procurement-review implementation. F04 publishes versioned certification/confirmation/readiness facts and invalidation events/contracts only; keep F05 integration behind an interface/feature flag until available.
- F06 owns historical import execution. F04 provides the represented-versus-recorded timestamp model and retroactive certification/confirmation APIs for a trusted migration caller.

## Exit gate

Every terminal F04 outcome is tied to immutable plan/attendance/certification/request versions and hashes, a verifiable authorized actor/source/action history, and replay-safe notification/job evidence. Vendor content and product-owner annotations remain separate; Linear status, transport receipts, reminders, timeout, silence, auto-replies, forwarded links and ambiguous replies never manufacture acceptance or confirmation. Production email/reply acceptance remains blocked until G4 external prerequisites are supplied.
