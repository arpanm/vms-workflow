# F07 — API and Swagger Documentation

## Final integrated reconciliation — 2026-07-30

The documented hardening surface applies through production migrations V1–V43
(V42 repeated-reopen; V43 durable migration). Local system 7/7 and schema
validation pass. Production identity/provider approval remains external, and
focused recovery evidence does not imply clean full-suite Maven/browser runs.

The executable contract is generated by springdoc from the Spring controllers
and Jakarta validation annotations.

## Accessing the contract

- OpenAPI JSON: `GET /v3/api-docs`
- Swagger UI: `GET /swagger-ui.html`
- Authentication: both require a valid bearer JWT.
- Actuator: only `/actuator/health`, `/actuator/health/liveness` and
  `/actuator/health/readiness` are public. Other actuator routes are denied;
  health never shows component/dependency details.

Production access still requires an approved issuer, audience, JWKS endpoint
and active server-side role assignments. Swagger “Authorize” cannot create
authority.

Background workers add no API contract. Finance, certification and migration
recovery run only in non-web profiles with Flyway disabled. The migration
recovery entry point is package-private, requires the live database lease and
uses a fixed system actor; it has no controller mapping and cannot be invoked
by a bearer token.

## Common HTTP contract

- Base API prefix: `/api/v1`.
- JSON mutations validate size and fields; retention mutations require
  `Idempotency-Key`.
- Clients may send `X-Correlation-Id`; responses expose the trusted
  correlation ID.
- Errors use safe RFC 7807 problem details. Internal SQL, stack traces,
  credentials, object keys, provider payloads and raw personal data are not
  part of the public contract.
- Browser CORS accepts only exact configured origins and bearer headers;
  cookies/credentials are not enabled.
- Rate-limited operations return `429` and `Retry-After`.

## Retention, classification and legal hold

Base path: `/api/v1/governance/retention`.

| Method and route | Required authority | Request / behavior |
|---|---|---|
| `POST /schedules` | Active organization `retention.schedule.manage` | Body: `organizationId`, allowlisted `recordClass`, `retentionDays` (1–36,500), `policyReference`, `effectiveFrom`; appends a version. |
| `GET /schedules?organizationId=` | Same | Lists configured immutable schedule versions for the authorized organization. |
| `POST /runs/dry-run` | Active organization `retention.execute` | Body: `organizationId`, `recordClass`, `asOf`; records deterministic eligible/held/not-due candidates without expiring capability. |
| `POST /runs/{runId}/execute` | Same run scope | Executes one owned attempt, rechecks current state/hold and appends result/proof transitions. |
| `POST /runs/{runId}/dead-letter-recovery` | Same run scope | Body: `reasonCode`; authorizes a new bounded cycle only after dead letter. |
| `GET /runs/{runId}` | Same run scope | Reads candidates, transitions, execution outcomes and expiry proofs. |
| `POST /artifacts/{artifactId}/holds` | Active organization `legal-hold.manage` | Body: `reasonCode`; places an append-only hold. |
| `POST /artifacts/{artifactId}/holds/{holdId}/release` | Same | Body: `reasonCode`; releases directly only when policy allows, otherwise records the first request. |
| `POST /artifacts/{artifactId}/holds/{holdId}/release-approval` | Distinct active actor | Body: `reasonCode`; approves two-person release and appends transition evidence. |
| `GET /classification?organizationId=` | `retention.schedule.manage` | Returns the local classification/handling inventory, including prohibited commercial-data boundary. |

Supported local retention record classes are
`TEMPORARY_EXPORT_CAPABILITY` and `TEMPORARY_PACKAGE_SHARE`. Execution expires
the access capability; it does not delete immutable closed evidence. Legal
holds exclude records at dry-run and are rechecked during execution.

## Server-authoritative feature flags

Base path: `/api/v1/governance/feature-flags`.

| Method and route | Required authority | Request / behavior |
|---|---|---|
| `POST /` | Active platform `feature.flag.manage` | Defines a unique dotted lowercase key, owner, safe default, description and reason. |
| `POST /{key}/versions` | Platform or active scoped `feature.flag.manage` | Appends SYSTEM, ORGANIZATION or ENGAGEMENT version with effective window, dependencies and reason. |
| `GET /{key}/evaluation?organizationId=&engagementId=` | Active scoped `feature.flag.read` | Evaluates scope precedence, time window and dependencies. Returns `authorizationGranted: false` by design. |

Scope precedence is ENGAGEMENT, then ORGANIZATION, then SYSTEM, then the
definition default. Self-dependencies and transitive cycles are rejected.
Engagement scope must belong to the supplied authorized organization.

## Health and metrics contract

Public readiness returns only stable status/code/time fields. Mandatory
database/workflow failure makes readiness unavailable; optional provider
configuration is reported as degraded without exposing hostnames, credentials
or tenant data. Metrics use route templates/status classes and operational
gauges, never raw resource IDs, names, email, tenant IDs or tokens.

Prometheus/other actuator endpoints are not publicly exposed by the application
security chain. Production metrics export and paging remain an external
deployment decision.
