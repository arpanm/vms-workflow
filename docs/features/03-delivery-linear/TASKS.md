# F03 — Deliverable Planning and Linear Tasks

**Phase:** 3
**Traceability:** RQ-011–RQ-017; PRD 02, 03, 07, 09, 13–16, 19, 20, 22
**Controlling stack:** Java 25 / Spring Boot 4.1.0 / PostgreSQL + Flyway / Vite React-TanStack. Do not add Supabase/Lovable features or migrations.

## Scope and delivery boundary

The locally implementable vertical is provider-neutral: planning/versioning, approvals, immutable snapshots, an allowlisted `LinearAdapter` contract with recorded fixtures, webhook verification/queue interfaces, reconciliation/job state, health UI, email-outbox contract, secured REST/OpenAPI APIs, and tests. It must be usable with a fake/recorded adapter and must never store salary, payroll, rate, markup, or employee billing-allocation fields.

The following production integrations are **externally blocked**, not silently emulated: Reliance approval of the Linear OAuth application/app actor, workspace/team/scopes, secret storage and webhook endpoint/secret; live GraphQL schema/credentials and webhook registration; and selection/authorization of the commitment-email provider, sender, Procurement contact group and controlled mailbox. Build configuration/readiness states and adapters, but do not claim live connectivity or send real mail before these inputs exist (PRD 19, 20).

## Exit gate

Lost, duplicate, invalid or replayed webhooks do not corrupt state; a provider outage leaves retained, explicitly stale data; live Linear state cannot rewrite an immutable snapshot; and Linear `Done` cannot certify delivery. Live OAuth/webhook/email production acceptance remains blocked until the named tenant approvals and credentials are supplied.
